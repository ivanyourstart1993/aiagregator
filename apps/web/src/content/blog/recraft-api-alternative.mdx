## Why we're upfront about not running Recraft

Recraft is its own model family, served through Recraft's own API and app, and part of what it's known for — true SVG vector output — is a capability the models on this gateway don't replicate. We don't run Recraft, and any "Recraft API" that isn't Recraft itself is either reselling their API under a markup or quietly swapping in a different model and calling it Recraft. ## What Recraft is known for, and what reproduces it (and what doesn't)

Recraft built its reputation on a few specific things: generating true vector (SVG) graphics rather than rasterized pixels, holding a consistent brand style (fixed color palette, line weight, icon set) across many generations, and clean flat-illustration or icon aesthetics. Split those apart:

- **Native SVG/vector output** — no model on this gateway produces true vector paths. If your build pipeline needs an actual `.svg` with editable paths, Recraft (or a vector tracer run on a raster output) is the only honest answer.
- **Flat, on-brand icon and illustration style** — this is a raster look, and it's very reachable. **gpt-image-1** and **DALL·E 3** both handle flat, graphic, low-detail icon/illustration prompts well and render any accompanying text legibly.
- **Style consistency across a batch** — **Nano Banana (Gemini image)** is the strongest instruction-follower on the gateway, so it's the best pick when you're feeding back a reference image or a fixed style description ("same three-color palette, same 2px outline") across a run of generations.
- **Photoreal brand mockups** (product shots, packaging in-context) — **Imagen 4** is the strongest photoreal option when the brief moves from flat/vector into a real-photo backdrop.

None of these outputs a vector file, and none is a pixel-for-pixel Recraft clone. What you get is the same category of programmatic, prepaid, single-endpoint access to brand-style raster imagery — rasterize-then-trace downstream if you need paths.

## Generate a comparable image

List the exact model codes live on your account before hardcoding one — codes change as providers ship new versions:

```bash
curl "https://api.aigenway.com/v1/methods?provider=openai_image" \
  -H "Authorization: Bearer sk_live_..."
```

Then call gpt-image-1 for a flat, on-brand icon set entry — the closest single-call match to what a Recraft icon request is usually asked to do:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai_image",
    "model": "gpt-image-1",
    "method": "text_to_image",
    "params": {
      "prompt": "a flat vector-style icon of a rocket launching, two-color palette navy and orange, thin 2px outline, white background, minimal geometric shapes",
      "size": "1024x1024"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a timeout and you get the same result back instead of paying for a duplicate generation.

## Hold a brand style across a batch

Recraft's other headline feature is style consistency: generate ten icons and have them look like one set, not ten unrelated images. Nano Banana is the strongest fit for that, because it follows a fixed style instruction (and an optional reference image) more reliably across repeated calls than a plain text-to-image model:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "gemini-3.1-flash-image-preview",
    "method": "text_to_image",
    "params": {
      "prompt": "flat vector-style icon of a shield with a checkmark, same two-color palette navy and orange, same 2px outline weight, white background, matching the rocket icon style",
      "aspect_ratio": "1:1"
    }
  }'
```

Both calls return a task in the same shape — poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a webhook deliver the finished image instead of holding a connection open. Keep your palette, outline weight and composition rules fixed in every prompt across a batch and re-run the same call per icon; that's what keeps a set looking related without a dedicated "brand style" feature. See the [task lifecycle](/docs/task-lifecycle) docs for the exact status fields.
