## Why we're upfront about not running Qwen Image

Qwen Image is Alibaba's own model, served through Alibaba Cloud's DashScope API and the open-weight release on Hugging Face. We don't run it, and any "Qwen Image API" that isn't Alibaba's own infrastructure is either reselling DashScope under a markup or quietly swapping in a different model while keeping the Qwen name. We won't do either. If your pipeline specifically depends on Qwen Image's exact weights — self-hosted or via DashScope — that's Alibaba's stack to deliver, not ours. If what you need is the *output category* Qwen Image is known for, keep reading.

## What Qwen Image is known for, and what reproduces it

Qwen Image built its reputation on a handful of specific strengths: unusually accurate rendering of dense and multi-line text (including Chinese, Japanese and Korean characters that most Western models garble), strong prompt adherence on complex multi-object layouts, and a companion editing model (Qwen-Image-Edit) for targeted, instruction-based image edits. Split those apart by which gateway model fits best:

- **Precise, legible in-image text** — **gpt-image-1** is the strongest text-rendering option on the gateway for Latin-script copy; it's the closest single-call match to a Qwen-style poster, diagram or UI mockup with a specific string that has to come out spelled correctly.
- **Complex, multi-constraint layouts** — **Nano Banana (Gemini image)** is the best instruction-follower on the gateway, so it's the closest match when a prompt lists several hard constraints (object count, position, text placement) that all need to hold at once.
- **Photoreal scenes with text overlays** — **Imagen 4** handles a camera-real backdrop with composed text or labels better than a flat-graphic model.
- **Fast, single-shot baseline compositions** — **DALL·E 3** is a dependable general-purpose option when the brief is simpler and speed matters more than pixel-perfect typography.

None of these ships Qwen Image's specific CJK text-rendering training, and none is a pixel-for-pixel clone. For non-Latin scripts, gpt-image-1 and Nano Banana are the best starting points on the gateway, but expect more regeneration than Qwen Image itself needs on that specific strength. What you get is the same category of programmatic, prepaid, single-endpoint access to precise-text and complex-layout generation, without a separate DashScope account.

## Generate a comparable image

List the exact model codes live on your account before hardcoding one — codes change as providers ship new versions:

```bash
curl "https://api.aigenway.com/v1/methods?provider=openai_image" \
  -H "Authorization: Bearer sk_live_..."
```

Then call gpt-image-1 for a layout with specific, legible copy — the closest single-call match to what a Qwen Image request is usually asked to do:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai_image",
    "model": "gpt-image-1",
    "method": "text_to_image",
    "params": {
      "prompt": "a product infographic with the headline text SPEC SHEET at the top, three labeled callout boxes reading POWER, WEIGHT, RUNTIME below it, clean flat vector style, white background",
      "size": "1024x1024"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a timeout and you get the same result back instead of paying for a duplicate generation.

## Test complex-layout accuracy across models without rewriting your integration

Because layout and text accuracy vary by model and by prompt, the fastest way to find your best fit is a side-by-side, not a single bet. Every model shares the identical `provider` / `model` / `method` / `params` shape, so switching is a one-line change:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "gemini-3.1-flash-image-preview",
    "method": "text_to_image",
    "params": {
      "prompt": "a product infographic with the headline text SPEC SHEET at the top, three labeled callout boxes reading POWER, WEIGHT, RUNTIME below it, clean flat vector style, white background",
      "aspect_ratio": "1:1"
    }
  }'
```

Both calls return a task in the same shape — poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a webhook deliver the finished image instead of holding a connection open. Keep the exact same headline and label strings fixed across two or three models and you'll spot which one holds the layout and spelling cleanest, faster than regenerating on one model over and over. See the [task lifecycle](/docs/task-lifecycle) docs for the exact status fields.
