## Why we're upfront about not running Adobe Firefly

Firefly is Adobe's own model family, deeply wired into Photoshop, Illustrator and the Firefly web app — generative fill, text effects, vector recoloring, and a training set Adobe markets as licensed for commercial safety. Adobe does publish a Firefly Services API, but it's Adobe's platform to sell, gated behind an Adobe Developer Console app and Creative Cloud/Firefly Services entitlements. We don't run Firefly's models, and we won't relabel a different model as "Firefly" to make a sale. If your workflow specifically depends on Firefly's Photoshop integration or its IP-indemnified training claims, that's Adobe's product to deliver. If what you need is the *output category* Firefly is known for — clean, prompt-driven image generation you can trust in a commercial pipeline — keep reading.

## What Adobe Firefly is known for, and what reproduces it

Firefly built its reputation on a few specific strengths: fast text-to-image generation tuned for design work, reliable text rendering for posters and social graphics, and commercially-safe output backed by Adobe's licensing story. Split those apart by which gateway model fits best:

- **General-purpose design generation** — **gpt-image-1** and **DALL·E 3** both handle short, direct prompts well and produce clean, presentation-ready compositions similar to what Firefly's text-to-image module outputs.
- **Legible in-image text (posters, banners, social graphics)** — **gpt-image-1** is the strongest at rendering readable copy inside an image, the same job Firefly's text-effects tooling targets.
- **Precise instruction-following and iterative edits** — **Nano Banana (Gemini image)** follows detailed, multi-constraint prompts closely, a good match for the kind of controlled generative-fill-style edits Firefly users lean on inside Photoshop.
- **Photoreal, camera-accurate output** — **Imagen 4** is the strongest photoreal option when a brief moves from stylized design work into a realistic product or scene render.

None of these ships Adobe's specific licensing indemnity or its Photoshop plugin. What you get is the same category of programmatic, single-endpoint access to fast, clean, design-ready image generation, callable from a backend instead of a desktop app.

## Generate a comparable image

List the exact model codes live on your account before hardcoding one — codes change as providers ship new versions:

```bash
curl "https://api.aigenway.com/v1/methods?provider=openai_image" \
  -H "Authorization: Bearer sk_live_..."
```

Then call gpt-image-1 for a clean, design-ready graphic with legible text — the closest single-call match to a Firefly poster or social asset:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai_image",
    "model": "gpt-image-1",
    "method": "text_to_image",
    "params": {
      "prompt": "minimalist product launch poster, bold sans-serif headline reading SPRING SALE, soft gradient background, plenty of clean whitespace",
      "size": "1024x1536"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a timeout and you get the same result back instead of paying for a duplicate generation.

## Do a Firefly-style generative edit

Firefly's other headline feature inside Photoshop is generative fill — extending or altering part of an existing image from a text instruction. Nano Banana handles the same kind of targeted, instruction-driven edit from an input image:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "gemini-3.1-flash-image-preview",
    "method": "image_to_image",
    "params": {
      "prompt": "extend the background to the left, adding matching soft studio lighting and seamless floor continuation",
      "image_url": "https://example.com/product-shot.jpg"
    }
  }'
```

Both calls return a task in the same shape — poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a webhook deliver the finished image instead of holding a connection open. See the [task lifecycle](/docs/task-lifecycle) docs for the exact status fields.
