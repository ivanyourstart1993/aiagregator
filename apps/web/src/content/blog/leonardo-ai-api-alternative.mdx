## What Leonardo AI is known for, and what reproduces it

Leonardo built its user base on a few specific strengths: production-ready concept art and character design, consistent game-asset generation (icons, environments, item sets), and fine-tuned models tuned for specific visual styles. Split those apart by which gateway model fits best:

- **Concept art and character design** — **Imagen 4** and **DALL·E 3** both handle painterly, art-directed prompts well, producing the kind of composed, detailed scene work a concept artist would use as a starting frame.
- **Game asset sets (icons, props, environment tiles)** — **gpt-image-1** renders clean, graphic compositions with legible in-image text, useful for UI icons, item cards, and anything with a label baked into the art.
- **Style consistency across a batch** — **Nano Banana (Gemini image)** is the strongest instruction-follower on the gateway, so it's the closest match to Leonardo's fine-tuned-model consistency when you feed it a fixed style description (or a reference image) across many generations instead of training your own checkpoint.
- **Photoreal product or environment renders** — **Imagen 4** is the strongest photoreal option when a brief moves from stylized concept art into a camera-real render.

None of these is a custom fine-tune of your own data, and none is a pixel-for-pixel Leonardo clone. What you get is the same category of programmatic, single-endpoint access to production-ready image generation, without training or hosting your own model.

## Generate a comparable image

List the exact model codes live on your account before hardcoding one — codes change as providers ship new versions:

```bash
curl "https://api.aigenway.com/v1/methods?provider=google_banana" \
  -H "Authorization: Bearer sk_live_..."
```

Then call Imagen 4 for a concept-art-style render — the closest single-call match to a Leonardo character or environment piece:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "imagen-4.0-ultra-generate-001",
    "method": "text_to_image",
    "params": {
      "prompt": "a battle-worn sci-fi ranger character concept, detailed armor plating, dramatic rim lighting, painterly digital art style, full body, plain background",
      "aspect_ratio": "3:4"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a timeout and you get the same result back instead of paying for a duplicate generation.

## Hold a consistent asset style across a batch

Leonardo's other headline feature is a fine-tuned model that keeps a whole asset set looking related. Without training your own checkpoint, Nano Banana gets you close by following a fixed style instruction reliably across repeated calls:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "gemini-3.1-flash-image-preview",
    "method": "text_to_image",
    "params": {
      "prompt": "game icon of a healing potion, same painterly digital art style and rim lighting as the sci-fi ranger character, square item-card composition, plain background",
      "aspect_ratio": "1:1"
    }
  }'
```

Both calls return a task in the same shape — poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a webhook deliver the finished image instead of holding a connection open. Keep the style description (lighting, rendering technique, level of detail) fixed across every prompt in a batch; that's what holds a set together without a dedicated fine-tune. See the [task lifecycle](/docs/task-lifecycle) docs for the exact status fields.
