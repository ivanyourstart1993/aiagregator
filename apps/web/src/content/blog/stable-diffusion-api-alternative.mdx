Stable Diffusion is not hosted on this gateway — no GPU rental, no self-hosted checkpoint, no Automatic1111 instance to babysit. Here's the honest alternative: if what you actually need is flexible, prompt-driven image generation behind a clean API, Nano Banana, Imagen 4, gpt-image-1 and DALL·E 3 cover that ground behind one key, one task contract, and prepaid USD billing.

## Why we're upfront about not running Stable Diffusion

Stable Diffusion is open-weight, which is exactly why it's usually self-hosted rather than called through a single canonical API — Stability AI offers its own hosted endpoints, but most "Stable Diffusion API" traffic actually runs on someone's own GPU box, a rented instance, or a third-party wrapper around a specific checkpoint and LoRA stack. That's a real option if you want full control over the model weights and are willing to own the infrastructure: provisioning GPUs, managing VRAM, updating drivers, and redeploying every time you swap checkpoints. We don't run Stable Diffusion, and we're not going to dress up a proxy to someone else's box as something it isn't. If you need the exact weights and full pipeline control, self-host. If you need the *category* of output people reach for Stable Diffusion to get, keep reading.

## What Stable Diffusion is known for, and what reproduces it

Stable Diffusion's reputation rests on three things: open weights you can fine-tune or run offline, deep customization through LoRAs, ControlNet, and custom checkpoints, and broad stylistic range from photoreal to heavily stylized. If your use case actually needs offline weights or a fine-tuned checkpoint, nothing hosted replaces that. But if what you need is the *output* — flexible, style-adaptable images from a prompt, without owning the pipeline — several models on the gateway cover that ground:

- **Nano Banana (Gemini image)** — best at instruction-following and iterative edits; use it when you need precise control over a prompt's constraints or want to revise an existing image, the closest analog to steering a diffusion pipeline with img2img.
- **Imagen 4** — strong photorealism and composition, a solid substitute when your Stable Diffusion checkpoint was tuned for camera-real output.
- **gpt-image-1** — reliable text rendering inside the image, useful for the poster, mockup, and UI-screenshot briefs that used to need a custom-trained checkpoint just to get legible copy.
- **DALL·E 3** — a dependable stylized baseline for fast, single-shot generation without prompt-weighting or negative-prompt tuning.

None of these is a drop-in Stable Diffusion checkpoint — you lose LoRA-level control over a specific look. What you get in exchange is zero infrastructure, a hosted endpoint that doesn't need a GPU, and the same category of programmatic, prepaid access.

## Generate a comparable image

List the exact model codes live on your account before hardcoding one — codes change as providers ship new versions:

```bash
curl "https://api.aigenway.com/v1/methods?provider=google_banana" \
  -H "Authorization: Bearer sk_live_..."
```

Then call Imagen 4 for a photoreal shot with tight prompt adherence — the closest single-call match to a well-tuned Stable Diffusion checkpoint run at high steps:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "imagen-4.0-ultra-generate-001",
    "method": "text_to_image",
    "params": {
      "prompt": "a weathered fantasy castle on a floating island at sunset, dramatic volumetric light, highly detailed matte painting",
      "aspect_ratio": "16:9"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a timeout and you get the same result back instead of paying for a duplicate generation.

## Test image-to-image edits without a ControlNet pipeline

A lot of Stable Diffusion workflows lean on img2img or ControlNet to steer a generation from a reference image rather than a prompt alone. Nano Banana handles that same job as a plain API call — send an existing image and an instruction, get back an edited result, no pipeline to wire up:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "gemini-2.5-flash-image",
    "method": "image_to_image",
    "params": {
      "prompt": "change the lighting to golden hour and add fog around the base of the castle",
      "image_url": "https://example.com/castle-draft.png"
    }
  }'
```

Both calls return a task in the same shape — poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a webhook deliver the finished image instead of holding a connection open. See the [task lifecycle](/docs/task-lifecycle) docs for the exact status fields.
