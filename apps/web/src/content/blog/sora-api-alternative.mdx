OpenAI's Sora is an app and a web product, not a public API — there's no `POST` endpoint you can put a key against, official or otherwise. If you're building a product that needs text-to-video or image-to-video on demand, the honest alternative isn't a wrapper around Sora's consumer app; it's calling Kling, Veo 3 or Seedance directly, behind one API key and one task contract.

## Why there's no Sora API to call

Sora ships as a standalone app (web and mobile) with generation, remixing and a social feed built around it — OpenAI has talked publicly about API access without shipping a stable, generally-available endpoint. That leaves two honest paths: wait, or use a video model that already has a documented, billed API today. We don't run Sora and we're not going to sell you a scraper that logs into the Sora app on your behalf — that's a TOS problem and a reliability problem, since it breaks the moment OpenAI changes the frontend. What we do run is a gateway in front of the video models that already ship real APIs.

## What reproduces Sora's use case today

Sora's pitch is text-to-video and image-to-video with strong prompt adherence and physically plausible motion. Three models on the gateway cover that ground from different angles, and none of them require a Sora account to reach:

- **Veo 3** — Google's flagship, the only one here with native audio generated in the same pass as the picture; closest fit if your output needs sound baked in, not added in post.
- **Kling** — strongest motion fidelity and character consistency across a clip, plus a Motion Control mode for repeatable choreography.
- **Seedance** — the cheapest and fastest of the three per second, the default when you're generating at volume rather than a single hero shot.

Confirm the exact model codes and current per-second pricing live on your account before you hardcode one — providers update their lineups on their own schedule:

```bash
curl "https://api.aigenway.com/v1/methods?provider=kling" \
  -H "Authorization: Bearer sk_live_..."
```

## Generate a clip the same way you'd call Sora

Every model on the gateway takes the same envelope — `provider`, `model`, `method`, `params` — so this is the request whether you land on Kling, Veo 3 or Seedance:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "kling",
    "model": "kling-v2-master",
    "method": "text_to_video",
    "params": {
      "prompt": "a paper boat drifting down a rain-slicked city gutter, shot from water level",
      "duration": 5,
      "aspect_ratio": "16:9"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a dropped connection and you get the same task back instead of paying for a second render. The response is a task in `queued` or `processing` state; nothing here is synchronous.

## Swap models without rewriting your integration

Because `params` keeps the same shape across models, comparing Sora-class output across providers is a one-line change, not three SDKs. Point the same prompt at Veo 3 instead:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "veo",
    "model": "veo-3",
    "method": "text_to_video",
    "params": {
      "prompt": "a paper boat drifting down a rain-slicked city gutter, shot from water level",
      "duration": 5
    }
  }'
```

Or `seedance` / `seedance-1-pro` (confirm the exact code via `/v1/methods`) when you're generating drafts or social variants at volume instead of one hero clip. Poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a signed webhook deliver the finished video — same status fields and payload shape regardless of which provider rendered it. See the [task lifecycle](/docs/task-lifecycle) docs for the exact states.

## The honest trade-off vs waiting for Sora

If your product specifically needs Sora's exact look, nothing here is a pixel-for-pixel substitute, and no amount of prompt engineering changes that — the fair thing to say is: wait for OpenAI to ship a real API, or ship today on a model that already has one. What you get by not waiting:

- **A documented, billed API now.** Kling, Veo 3 and Seedance are called through their own supported endpoints, not a scraped consumer app that can change without notice.
- **One task contract for all three.** `provider` / `model` / `method` / `params` stays identical, so trying a second model when Sora's API does eventually ship is a config change, not a rewrite.
- **Prepaid USD, no waitlist.** Top up a balance, generate video today, and re-evaluate Sora later without having built your product around a placeholder.

If Sora's API ships and fits your use case better, moving to it later is easier from a working integration than from nothing. Until then, Kling, Veo 3 and Seedance behind one key cover the same job.
