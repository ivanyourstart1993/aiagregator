## What FLUX is known for, and what reproduces it

FLUX earned its reputation on three things: tight prompt adherence (it renders what you asked for, including legible text, without heavy re-rolling), strong photorealism at speed, and a permissively licensed open-weight tier alongside a hosted Pro tier. You don't need FLUX specifically to hit that brief — several models on the gateway cover the same territory from different angles:

- **Nano Banana (Gemini image)** — the closest match for prompt adherence and instruction-following; strong when the brief has several constraints the model needs to actually obey, or when you're editing an existing image rather than starting fresh.
- **Imagen 4** — the strongest photoreal, camera-real output on the gateway; a good fit when FLUX's appeal for you was "looks like a real photo," not stylization.
- **gpt-image-1** — reliable text rendering inside the image, useful for the poster/mockup/UI-screenshot use cases where FLUX's text accuracy usually gets cited.
- **DALL·E 3** — a dependable general-purpose baseline when you want a fast, single-shot result without much prompt engineering.

None of these is a drop-in FLUX replacement — the exact pixels will differ. What you get is the same category of programmatic, prepaid, single-endpoint access, without an account on a separate provider.

## Generate a comparable image

List the exact model codes live on your account before hardcoding one — codes change as providers ship new versions:

```bash
curl "https://api.aigenway.com/v1/methods?provider=google_banana" \
  -H "Authorization: Bearer sk_live_..."
```

Then call Imagen 4 for a photoreal shot with tight adherence to a detailed prompt — the closest single-call match to what a FLUX Pro request is usually asked to do:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "google_banana",
    "model": "imagen-4.0-ultra-generate-001",
    "method": "text_to_image",
    "params": {
      "prompt": "a product shot of a matte black wireless earbud case on a marble surface, studio softbox lighting, shallow depth of field, sharp focus on the logo",
      "aspect_ratio": "1:1"
    }
  }'
```

`Idempotency-Key` makes retries safe — resend the same key after a timeout and you get the same result back instead of paying for a duplicate generation.

## Test prompt adherence across models without rewriting your integration

FLUX's biggest selling point for a lot of teams is that it does what the prompt says, including rendering readable text. That's exactly where gpt-image-1 is strong, so it's a natural side-by-side. Every model shares the identical `provider` / `model` / `method` / `params` shape, so switching is a one-line change:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "openai_image",
    "model": "gpt-image-1",
    "method": "text_to_image",
    "params": {
      "prompt": "a storefront sign reading OPEN 24 HOURS in neon script above a corner bakery, dusk lighting",
      "size": "1024x1024"
    }
  }'
```

Both calls return a task in the same shape — poll `GET /v1/generations/{task_id}` or set a `callback_url` and let a webhook deliver the finished image instead of holding a connection open. Keep two or three representative prompts as a fixed test set and you'll find which model matches your brief faster than tuning guidance-scale parameters on one model ever did. See the [task lifecycle](/docs/task-lifecycle) docs for the exact status fields.
