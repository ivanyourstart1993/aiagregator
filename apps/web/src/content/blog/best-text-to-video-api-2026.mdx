"Best text-to-video API" depends on what the prompt has to carry — Veo 3, Kling and Seedance all turn a scene description into a clip, but they diverge on audio, motion control and cost per second. This is the roundup with the actual request shape, so you can run a prompt against all three instead of trusting a vendor's showreel.

## What text-to-video actually has to invent

Unlike image-to-video, where a source frame locks in composition and subject, text-to-video asks the model to invent everything — framing, lighting, subject appearance and motion — from words alone, which is why the same prompt can land cleanly on one run and come back malformed on the next. Veo 3's differentiator is generating audio in the same pass: dialogue, ambient sound and effects synced to the picture, not a silent clip you dub afterward. Kling leans the other way, prioritizing motion fidelity and camera control for a prompt-only scene, plus a `motion_control` mode when you later want to transfer a reference movement onto a character. Seedance trades a bit of that polish for speed and a lower cost per second, which is the right call when you're generating ten prompt variations and keeping one, not rendering a single hero shot. Providers rev model lineups on their own schedule, so confirm what's actually live on your account before you build around a specific version:

```bash
curl "https://api.aigenway.com/v1/methods?provider=veo" \
  -H "Authorization: Bearer sk_live_..."

curl "https://api.aigenway.com/v1/methods?provider=kling" \
  -H "Authorization: Bearer sk_live_..."

curl "https://api.aigenway.com/v1/methods?provider=seedance" \
  -H "Authorization: Bearer sk_live_..."
```

Each call returns the live `model` and `method` values for that provider, plus current per-second pricing — more reliable than any fixed table, including this one.

## One request shape, three providers

Every model on the gateway shares the same task contract, so running a prompt across all three is a one-line change to `provider` and `model` — not three SDKs and three sets of docs:

```bash
curl -X POST https://api.aigenway.com/v1/generations \
  -H "Authorization: Bearer sk_live_..." \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "kling",
    "model": "kling-v2-master",
    "method": "text_to_video",
    "params": {
      "prompt": "a lighthouse beam sweeping over a stormy coastline at night, slow cinematic pan",
      "duration": 5,
      "aspect_ratio": "16:9"
    }
  }'
```

Swap `"provider": "kling"` / `"model": "kling-v2-master"` for `veo` / `veo-3` or `seedance` / `seedance-1-pro` (confirmed live via `/v1/methods` for your account) and the identical prompt runs on all three — the only fair way to judge "best" on your own copy rather than a demo reel.

## It's an async task no matter which model you pick

None of these three return a finished clip inline — text-to-video takes seconds to minutes, so every submit hands back a task in `queued` or `processing` state, regardless of provider. Poll `GET /v1/generations/{task_id}` until the status flips to `completed` (or `failed`), or set a `callback_url` on the request and let the gateway push a signed webhook when the render is done — same payload shape, same status values, no matter which model produced the clip:

```bash
curl https://api.aigenway.com/v1/generations/task_8f2a1c \
  -H "Authorization: Bearer sk_live_..."
```

`Idempotency-Key` on the original submit means a retry after a dropped connection returns the existing task instead of paying for a second render — see the [task lifecycle](/docs/task-lifecycle) and [webhooks](/docs/webhooks) docs for the exact status transitions and signature check.

## Picking one for your actual use case

For a hero shot that needs dialogue, voiceover or ambient sound baked in, Veo 3 is the only one of the three that generates audio natively in the same render — anything else means stitching a separate audio pass onto a silent clip. For b-roll, concept exploration or anything where camera movement and scene composition matter more than audio, Kling's motion fidelity and control tend to win, and its `motion_control` mode is there if you later need a character to repeat a specific movement across clips. For high-volume generation — batch previews, social variants, prompt A/B tests where you're keeping a fraction of what you render — Seedance's lower cost per second and faster turnaround make the economics work in a way a premium model doesn't. None of this is permanent: pricing and quality shift as providers ship new versions, which is the real argument for not hardcoding a single "best" choice into your product.

## Why one gateway beats three provider accounts

Picking a single "best" text-to-video API up front locks you into whichever model wins today, but the ranking above changes as providers update their lineups and as your use case shifts from hero shots to batch drafts. Routing every call through one gateway means switching from Kling to Veo to Seedance — or running all three in parallel to compare — is a one-line change to `provider` and `model`, not a new SDK, a new billing relationship, and a new webhook handler to maintain. One API key, one task contract, prepaid USD billing across every provider, so this comparison stays something you re-run next quarter instead of a snapshot that's stale the moment a provider ships an update.
